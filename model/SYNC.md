# مزامنة بيانات التكلفة

`model_rows.json` المولَّد هنا تستهلكه أيضًا منصة تحليل المبيعات، حيث يُربط
بفواتير المبيعات لاحتساب الربحية لكل عميل ومندوب وعلامة تجارية وصنف.

| | |
|---|---|
| الوجهة | [`hannopo1/ABOHASHEM-sales-`](https://github.com/hannopo1/ABOHASHEM-sales-) |
| المسار هناك | `data/cost/model_rows.json` |
| المستهلِك | `analysis/13_join_cost_margin.py` |

## بعد أي تعديل على نموذج التكاليف

```bash
python3 model/costing_pricing_model.py     # يعيد توليد model_rows.json
# ثم انسخه إلى مستودع المبيعات وحدّث الالتزام في data/cost/PROVENANCE.md
```

هذا المستودع هو **المصدر الوحيد** لبيانات التكلفة. النسخة في مستودع المبيعات
مشتقّة ولا تُحرَّر مباشرة.

### قبل تعديل أي قائمة أو إعادة رفعها

قائمة **يونيو 2026** ليست قائمة عادية: هي **المرساة** التي تربط المستودعَين.
أرقامها — 3,741,772 / 2,039,933.08 / 1,701,838.92 / 418,841.92 — مكتوبة في
`analysis/13_join_cost_margin.py` وفي المستخرِج وفي الاختبارات على الجانب الآخر.

تغييرها **يُجهض** خط الأنابيب هناك بدل أن يُخرج رقمين متناقضين لشهر واحد. وهذا
مقصود: لو تغيّر نموذج التكاليف دون القائمة، أو العكس، لتوقف البناء ونُبِّه
المُحرِّر. إن كان التغيير مقصودًا، فالخطوة الصحيحة تحديث الطرفين معًا.

### إضافة قائمة شهر جديد

1. ارفع الوثيقة هنا.
2. في مستودع المبيعات: أضف مسارها إلى `PDF_SOURCES` (أو ورقتها إلى
   `XLSX_SHEETS`) في `analysis/tools/extract_income_statements.py`، ثم شغّله.
3. المستخرِج **يتوقف** إن لم تُطابق القائمةُ الجديدةُ متطابقاتِها الخاصة، أو إن
   لم تعد التغطية 13 شهرًا — وهو تذكير مقصود بتحديث العدد المتوقَّع.
